# 面向普通用户的交付与使用体验

更新日期：2026-11-13。本轮先记录方向与验收要求，后续再实施。以下安装包、引导、项目管理、托盘、数据迁移和更新机制均是待开发目标，不是当前 v1.2.3 已提供的能力；当前事实以[验证记录](validation.md)为准。

## 下一阶段的交付目标

交付一个可以让普通人独立使用的 Windows 桌面内测版。用户无需开发经验，也无需我们远程配置，能够完成：

**下载 → 安装 → 准备 CAD 和模型服务 → 创建第一个模型 → 修改 → 保存 → 退出 → 第二天继续。**

首轮以 Windows x64 和当前已验证的 FreeCAD 1.1.4 为适配基线，发布前复核兼容范围。SolidWorks / Fusion 继续作为后续适配方向；原网页/CadQuery 思路和实现保留，不作为普通用户的默认入口。趣味作品与加工、组装的长期目标保持不变。

## 使用形态

| 入口 | 用户用途 | 目标行为 |
|---|---|---|
| 完整工作台 | 管理项目、讨论方案、检查计划与结果 | 最近项目、对话、工程状态、保存位置、操作和验证记录清楚可见 |
| 悬浮小窗 | 在 CAD 中工作时随手交流和修改 | 保留当前项目、选择与任务，支持展开、收起和随时找回 |
| 托盘 | 收起后的恢复、连接状态和退出 | 首次明确说明收起行为，提供显式退出；退出助手保留 CAD 和未保存工程 |

两种窗口形态共享一个会话/任务来源。切换、隐藏或再次启动不能重复提交模型请求或 CAD 修改。托盘和项目管理尚未实现，窗口已有行为和剩余验收见[交互规格](desktop-harness.md)。

## 安装与首次启动

安装包负责携带经过验证的 Electron、独立 Node、DSH 及所需本地依赖。DSH 必须继续在独立 Node 中运行，不能因打包而改用 Electron run-as-node。用户不应自行安装 npm、运行脚本、改环境变量或手动执行连接宏。

现有 CAD 优先识别和复用；未安装时引导获取经过验证的版本，展示安装/下载状态和失败后的继续入口。不能静默替换已有 CAD 或更改用户工程。FreeCAD 是否随包提供、首次下载或仅引导安装，留给打包阶段根据体积、更新和分发条件确定。

首次启动分三步，可返回、恢复和重新检测：

| 步骤 | 界面应解释什么 | 验收结果 |
|---|---|---|
| 准备 CAD | 检测到的软件、版本、连接状态；缺少软件时怎样完成准备 | 无需开发者协助建立正确连接，只保留一个工作实例 |
| 连接模型 | 服务地址、模型、凭据输入及连接测试；失败原因和重试入口 | 能区分网络、凭据、模型不可用等问题；可重新配置 |
| 完成首个作品 | 从盒子等有边界的任务开始，理解确认、执行、检查和保存 | 用户完成一次创建、一次修改，并保存可重开的原生工程 |

内测先规划可在界面配置用户自己的模型服务，凭据交由受控后端/DSH 管理，桌面发行物不得内置共享密钥。面向普通人的正式版以登录即用为体验方向；托管服务、账号、费用及用量策略尚未决定，不作为本轮已经实现或承诺的服务。

每一步显示已完成项与下一步操作。准备中不要留下空白页面；配置失败不能要求用户阅读堆栈才能继续。

## 日常使用与工程续接

项目应明确关联 CAD 工程、保存位置、对话和操作记录。打开助手能看到最近项目及其状态，恢复时重新读取实际工程，不把恢复聊天等同于恢复 CAD 执行。

当前开发版是单会话，尚无完整项目中心。首版以助手创建、保存和续改的工程为主要验收对象；外来工程当前只读，要在入口说明范围，不能暗示用户导入任何工程都能编辑。

用户需要一直能看清：当前软件和工程、本次对象、正在进行的阶段、修改是否已执行、接下来能做什么。计划用普通语言描述变化与影响，工具参数按需展开。执行后显示实际读回的结果，并提供继续修改、保存、查看检查、撤销等符合当前状态的入口。

完整工作台与小窗都要验收流式阅读、生成中展开思考/工具、上翻历史、草稿保留和输入可见；工程状态更新不应抢走用户在 CAD 中的焦点。窗口关闭、托盘恢复、明确退出和任务中退出的含义要一致，避免每次普通收起都进入退出确认。

## 数据、恢复与稳定性

| 环节 | 后续要求 |
|---|---|
| 数据目录 | 设置/会话使用系统用户数据目录；日志/缓存与工程分开；原生工程保存到用户选择的位置。安装目录不承载持续写入的用户数据 |
| 旧数据迁移 | 兼容现有 `desktop/.data/` 与独立的原型数据；先备份和校验，再切换引用，保留原数据和失败恢复入口；不自动转换两端工程或搬动运行中的桥接目录 |
| 启动自检 | 核对运行时、模型服务、CAD 版本与组件、数据目录可写性；给出对应恢复动作 |
| 连接恢复 | 区分 CAD 已关闭、暂时无响应、组件需升级与工程已切换；优先复用原实例，不反复新开窗口 |
| 修改保护 | 保留确认、工程/对象指纹与事务边界；形成可验证的保存/恢复点，明确撤销范围；不承诺所有操作都能自动回滚 |
| 结果回传 | 持续保留已消费请求与实际结果的关联；文件重试只补发状态/结果，执行不确定时不重跑 CAD |
| 错误说明 | 区分模型、CAD、权限/占用和几何失败，说明已完成/未完成/待核对项；展示用户能采取的下一步 |
| 诊断支持 | 提供用户主动导出的脱敏诊断包；默认排除凭据、完整对话、模型/截图和个人路径，导出前可检查内容 |

目前私有数据默认仍在程序目录下，普通恢复、原生事务与部分文件故障已有验证，但它们不能代替安装后的数据分离、迁移和跨版本恢复验收。详细边界见[连接说明](cad-connection.md)及[验证记录](validation.md)。

## 发布与升级

优先采用成熟的 Electron 打包、签名和更新流程，参考[分发概览](https://www.electronjs.org/docs/latest/tutorial/distribution-overview)。具体工具与发布渠道在实施时选定，不预设当前已有安装包或自动更新服务。

发行物应完整携带运行依赖、原生模块、技能与已采用上游的许可/来源记录，并验证它们在打包路径中可以加载。更新需要协调助手、独立模型进程与 CAD 连接组件的版本；任务执行中不强制升级或关闭 CAD，组件升级保留工程与选择。更新失败后要能继续使用可工作的版本，并保护用户数据。

## 开发顺序与放行条件

| 顺序 | 工作包 | 完成条件 |
|---|---|---|
| P0 | 安装包、完整运行环境、用户数据目录与旧数据迁移 | 无开发环境的新 Windows 账户可安装和启动；目录可写、原生模块可用；现有数据迁移失败可恢复 |
| P1 | CAD/模型准备与首次作品引导 | 用户独立完成连接、创建、修改、保存和重开，不运行命令或手动宏 |
| P2 | 最近项目、工程续接、错误处理与诊断 | 退出/重开、断网/断连、权限/文件占用与执行不确定时，数据保留、状态清楚且无重复写入 |
| P3 | 整体交互打磨、托盘、小窗与更新体验 | 完成双形态、焦点、快捷键、多屏、收起/退出与跨版本更新回归 |
| 试用验收 | 邀请未接触项目的新用户独立使用 | 观察完整流程，记录卡点、失败及恢复过程，据此确定下一轮修复优先级 |

各包可先做必要的体验设计，发布前必须联合验收。用干净 Windows 账户测试安装、首次运行、普通用户权限、保存重开、更新与卸载；卸载默认保留用户工程和会话，删除数据需单独明确选择。中文/空格路径、短暂文件占用、失效凭据、离线、CAD 手改/切换/关闭、执行中退出及多屏等情况要有记录。

核心成功标准是新用户能够独立完成并续接自己的任务。现有43项普通测试和本机真实 CAD/模型记录仅证明对应开发能力；安装、升级、数据迁移与新用户体验需要各自新增证据。后续实物制作仍按[长期路线](roadmap.md)单独验证。
