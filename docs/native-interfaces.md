# FreeCAD 原生接口与现成工具复用

更新：2026-11-13，桌面开发版 v1.2.0。Agent 已接入66项明确的 FreeCAD 接口，不再只能调整旧示例的几个尺寸。实现复用 [seansackowitz/mcp-freecad](https://github.com/seansackowitz/mcp-freecad/tree/685341437f26f2a62e0122cdb893d09ae30b5034) 的 MIT handlers；本项目增加确认计划、文档范围、事务、几何检查和 DSH 适配。

## 能操作什么

| 接口组 | 数量 | 范围 |
|---|---:|---|
| `doc_*` | 3 | 创建工程、列出工程、重算 |
| `obj_*` | 8 | 对象列表、树、属性、标签、位置、属性修改与删除 |
| `sketch_*` | 12 | XY/XZ/YZ草图，线、折线、圆、圆弧、点，增删约束和几何、修改约束值 |
| `part_*` | 18 | 基本体、拉伸、旋转、放样、扫掠、布尔、圆角、倒角、镜像和阵列 |
| `pd_*` | 10 | 原生Body、Pad、Pocket、Revolution、Groove、圆角、倒角与阵列 |
| `expr_*` | 3 | 读取、设置、移除原生数值/参数表达式 |
| `sheet_*` | 4 | 参数表创建、读写单元格、别名 |
| `io_*` | 6 | STEP/IGES导入，STEP/IGES/STL/OBJ导出 |
| `view_*` | 2 | 标准观察方向与适应视图 |

66项中11项为实际读取或视图操作，55项进入待确认计划。另有 `freecad_native_plan`，让 Agent 一次提交最多100项明确接口步骤，减少复杂建模的工具往返。加上已有读取、截图、配方提案和技能读取，默认共71个注册工具；设置中归为5个开关，原生组展开可查看清单。

接口契约由固定版本源码的 AST 生成，见 [`native-catalog.json`](../desktop/native-catalog.json)。`freecad-native` 技能提供本地适配规则，保留上游README及按组拆分的参数说明，用 `skill_read(id, resource)` 按需加载。来源、许可证、原文件哈希及适配修改记录在 [`SOURCE.json`](../desktop/freecad/native_upstream/SOURCE.json)；重建脚本为 [`vendor-native-tools.py`](../scripts/vendor-native-tools.py)。运行时不依赖调研检出目录，不启动上游RPC服务器。

## 怎样使用

连接新版FreeCAD后，可说“做一架机身圆滑、机翼渐缩、有垂直尾翼的小飞机，长约150毫米”，或“给当前零件增加一个圆角”。Agent 读取实际工程，按需加载原生技能和接口参考，准备具体的草图、放样或特征编辑步骤。确认区可展开每项接口与参数，确认后才写入。

“做一个飞机”“做一个小飞机”交给原生Agent规划；只有明确“简化飞机”的离线指令保留旧平板结构示例。欢迎页的飞机示例也改为原生造型需求，避免普通用户一开始只得到平板。

工具返回 `planned:true, executed:false` 表示准备完成，新对象此时尚未存在于CAD。真正执行后会读回原生对象、几何和实际接口返回值；再获取截图检查外观。修改已有工程直接操作对应特征，不应新建一个工程代替修改。平滑机身可用多个截面放样，翼尖可调整对应草图的位置，无需为每种造型增加一个固定模板。

新对象使用唯一英文ID，中文显示名可另设；后续步骤按ID引用。原生工程有零件/对象列表和实际外形测量；尺寸来源于真实几何，不把表面当成实体。通用原生模型的尺寸通过属性、草图约束、表达式或参数表修改；旧配方的“设计尺寸”面板继续只服务配方。旧配方首次确认原生编辑时会明确转换模式，此后不再从旧配方整体重建。

显示同样可走接口：读取对象可见性与视图属性；确认后设置Visibility、ShapeColor/LineColor、Transparency或DisplayMode。镜像保留源零件显示。测量使用FreeCAD的[原生最优包围盒](https://freecad.github.io/API/db/d71/classPart_1_1TopoShapePy.html)，关闭显示三角网格参与计算，避免圆柱/球的尺寸随显示网格精度偏小。

## 写入与版本边界

- 每次计划仅操作当前受管工程，或首项显式创建的一个新工程；保留其他已打开工程。外来工程仍只读，可导出，不支持自动接管任意第三方特征树。
- 确认时重新核对工程、选择、几何、相关属性和参数表指纹。文档变化使旧计划失效，操作不会自动重放。
- 几何修改在一个原生事务内执行，重算并检查错误/无效几何；失败中止事务。新建失败只关闭本轮新建工程，保留原工作区。撤销/重做及保存重开后的原生编辑已做单独回归。
- 导出必须单独计划，不覆盖已有路径，并检查实际文件非空。导入检查确有新几何。STEP/IGES交换文件不承诺恢复原生建模历史；IGES可能是曲面/壳。
- 连接组件由助手自动安装与管理，支持在原窗口升级，保留工程和视角。首次在已经打开但未安装组件的旧CAD接入时，需保存后重开一次；不要求用户运行宏或Python，不反复另开窗口。见[连接说明](cad-connection.md)。

上游在FreeCAD 1.1.4的实测兼容修正包括草图平面旋转、Body归属/旋转轴引用、Draft极轴阵列参数，以及使用FreeCAD注册的 `Part.insert` 导入IGES。未把上游工具的成功返回当成充分证据。

没有接入任意Python执行、任意MCP服务、脚本式技能、装配运动求解、CAM或切片。原生打开/保存仍用应用按钮，工程关闭/切换不开放为模型写工具。工具数量不代表任意形状都能一次成功，接口成功也不代表造型、工艺、装配或气动正确。

## 验证

显式设置FREECAD_EXE后运行 `node desktop/test/native-interfaces-check.mjs`。已在FreeCAD 1.1.4中实际执行全部66项接口，检查解析体积/尺寸、参数联动、STEP/IGES导入和四种导出，并覆盖失败回滚、跨文档拒绝、首事务撤销/重做、保存重开后修改。摘要见 [`native-interfaces-results.json`](../desktop/validation/native-interfaces-results.json)。该批历史证据使用隔离实例；后续默认复用共享CAD，以独立工程隔离用例，不再反复新开窗口。这不是模型生成成功率测试。

`node desktop/test/run-native-model.mjs` 显式打开生产Electron界面和隔离CAD、调用真实模型，验证原生飞机创建、同工程翼尖修改、真实截图复查、流式工具与小窗。它会使用模型服务；结果与限制见[验证记录](validation.md)。普通 `npm test` 不调用模型或打开CAD。
