# 桌面 Harness 与悬浮小窗交互规格

更新日期：2026-11-13。本文是目标产品规格，尚未实现；当前可运行版本仍为网页与 CadQuery 验证原型。定位见[产品目标](product.md)，实现顺序见[实施路线](roadmap.md)。

## 一个应用、两种窗口形态

完整工作台和悬浮小窗属于同一个桌面应用，连接同一段对话、任务和 CAD 工程。用户在两种形态间切换时，不能出现上下文分叉或重复执行。

| 内容 | 完整工作台 | 悬浮小窗 |
|---|---|---|
| 对话 | 完整历史、附件和方案讨论 | 最近消息、简短回复与输入，按需展开历史 |
| 工程上下文 | 连接的软件实例、工程、对象与相关文件 | 至少显示当前工程和选中对象，长名称可展开查看 |
| 执行过程 | 计划、工具调用、进度、变更及检查结果 | 一行清楚的状态，必要确认和错误提示 |
| 操作控制 | 执行、暂停、取消、恢复及工程管理 | 暂停/取消、展开工作台和收起入口 |

正常使用以对话 Harness 为中心；专业 CAD 承载实际工程与编辑视图。辅助预览可以存在，但不能让用户误以为网页预览已修改 CAD 工程。

## 小窗行为

- 支持置顶、拖动、调整大小和紧凑布局，尽量少遮挡 CAD 工作区。
- 提供快捷键呼出、收起和切换形态；具体按键待检查与 CAD 快捷键冲突后确定。
- 呼出输入时可聚焦对话框；执行状态刷新和新回复不应反复抢走 CAD 的键盘焦点。
- 小窗展开到完整工作台，再缩回时恢复用户设置的位置和大小；多屏或显示器变化后，窗口应回到可见区域。
- 收起窗口不结束会话或擅自取消任务；恢复后能看到当前进度、必要确认和错误。置顶与系统通知的具体支持按目标系统验证。
- 明确区分收起窗口与退出应用。退出时若有任务，解释当前状态并让用户决定如何处理；不得连带关闭 CAD 或丢弃其未保存工程。
- 语音是后续可选输入，当前不作为已提供能力或首轮验收前提。

## 上下文与“这个”的含义

以实际 CAD 状态为依据读取软件实例、活动工程、单位、选中对象及其类型，例如零件、草图、特征或面。每次任务记录操作依据；对象名称仅用于展示，具体对象引用和失效检测由适配器验证实现。

用户在 CAD 中选中孔后说“这个改成8毫米”，小窗应能显示对应工程与孔对象，并明确本次目标。存在多选、无选择、多个同名对象或不支持的选择类型时先澄清。用户明确指定的其他对象需要解析和校验，不能忽略其指令而盲目使用选择。

当前网页的组件选择只证明了原型内部的指代传递，不等于已经读取到 SolidWorks 或 Fusion 的选择。

## 共享状态与切换

两种窗口形态共享对话历史、输入草稿、附件、目标工程、当前修改对象、计划、执行标识、进度、检查结果和待处理确认。它们是同一任务的两种展示，不能各自拥有独立写入队列。

执行中缩小或展开不重复提交请求；暂停后切换仍保持暂停；待确认的操作在任何形态中只能确认并执行一次。CAD 断开时两种形态都显示断连，不能继续显示旧连接为可用。

## 用户与助手协作

| 情况 | 期望行为 |
|---|---|
| 用户手动选中或编辑对象 | 更新上下文，下一次写入前重新校验 |
| 助手准备修改 | 明确目标工程、对象、变更范围和执行状态 |
| 执行期间用户切换工程或修改相关对象 | 暂停受影响步骤，重新读取并在必要时重新确认 |
| 无关的视图旋转或缩放 | 区分视图变化和设计修改，避免无故阻止用户查看 |
| 用户暂停 | 在适配器支持的安全边界停止后续步骤；显示是否仍有当前步骤在执行 |
| 用户取消 | 不再启动后续步骤，说明已完成变更和是否需要恢复；不宣称全部修改自动消失 |
| 部分失败或 CAD 断连 | 展示完成与失败范围，恢复连接后重新校验，不自动重复已完成写入 |
| 用户请求撤销或恢复 | 使用已验证的能力，说明影响范围；无法可靠恢复时明确交由用户检查 |

不默认通过全局锁住鼠标和键盘协调操作，也不通过杀进程取消 CAD 任务。具体任务边界、撤销单位和冲突检测能力，均须在首个 CAD 及其版本中验证。

## 目标架构边界

规划结构：**桌面界面（完整/小窗） → 共享 Harness 会话与任务服务 → CAD 适配器 → 用户正在使用的专业 CAD**。

适配器应逐项声明和验证读取工程、解析选择、执行操作、查询结果、保存、暂停/取消及撤销/恢复的能力。界面展示实际支持范围，不能把某一软件的验证结果当成另一软件也已支持。

首个 CAD 与版本、适配方式、桌面封装框架、对象引用方案和快捷键均待确定。现有 Node/DSH、对话记录、参数与验证代码按实际适用性复用，保留原型和用户数据，不以文档更新为由迁移或删除工程。

## 首轮交互验收

1. 从桌面应用启动进入完整 Harness；连接测试 CAD 并正确显示工程与选择。
2. 写入草稿、加入附件、启动任务后缩成小窗，再展开，状态连续且任务仅执行一次。
3. 在 CAD 中选择孔并说“这个改成8毫米”，实际原生工程修改正确，可见且可接手编辑。
4. 小窗能移动、调整大小、置顶和快捷呼出；状态更新不持续抢占 CAD 输入焦点。
5. 排队后切换文档、手动改变相关对象或关闭 CAD，不会继续按旧上下文写入。
6. 在两种形态下验证暂停、取消、部分失败、恢复和一次撤销；明确无法即时中断的步骤。
7. 收起、恢复窗口，以及执行中请求退出，均不会无提示丢失对话或 CAD 未保存工程。

以上是待实现验收清单。桌面交互通过仍不代表制造、配合和实物装配已通过，后续继续按控制盒试点验证。
