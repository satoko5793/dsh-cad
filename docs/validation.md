## 桌面与 FreeCAD 常驻桥接实测

### v1.2.0：66项现成原生接口

连接体验另作真实验收：助手通过FreeCADCmd探测实际用户目录、自动安装启动组件；FreeCAD用single-instance入口启动后自行连接，没有要求用户执行宏/Python。再次连接和第二会话复用一个进程；后续修改桥接源码后在原进程重载，文档令牌、几何、选择与相机保持。摘要：[自动连接](../desktop/validation/connector-results.json)、[原窗口升级](../desktop/validation/lifecycle-results.json)。当前没有独立安装包，首次已打开但未加载组件的旧CAD可能需保存后重开一次。完整流程见[连接说明](cad-connection.md)。

实际采用固定MIT版本mcp-freecad的handlers和工具说明，非只注册名称。`desktop/test/native-interfaces-check.mjs`在隔离FreeCAD 1.1.4里调用全部66项：基本体/曲面、草图平面、放样、旋转、扫掠、PartDesign特征、布尔、圆角、倒角、镜像/阵列、约束增删、参数表/表达式、对象属性/位置/标签/删除、只读树和视图，STEP/IGES导入与STEP/IGES/STL/OBJ导出。检查解析体积和尺寸、参数联动，并覆盖跨文档拒绝、失败批次回滚、初次建模事务撤销/重做、FCStd重开后继续编辑。新增显示属性回归检查镜像保留源对象、颜色/透明度和视图模式。摘要：[`native-interfaces-results.json`](../desktop/validation/native-interfaces-results.json)。

实测修正了上游XZ/YZ平面方向、PartDesign的Body/旋转轴引用、Draft极轴阵列参数、IGES接口静默不创建几何。导入要读回新几何、导出要检查非空文件。集成实测另发现镜像源对象被本地显示整理误隐藏，已修正并增加可见性上下文/接口；圆柱与球的测量使用不含显示网格的最优包围盒。FreeCAD错误中止事务，不自动重试或把planned当作已建模。

来源、技能references、精确边界及复现命令见[原生接口](native-interfaces.md)。全部接口有一次或多次正例，不表示所有参数组合、几何条件、FreeCAD版本或第三方工程都已覆盖。没有任意Python/MCP或外来工程接管，没有制造/装配/气动验证。

新的飞机模型使用37项原生操作，包含圆形截面放样的机身、渐缩主翼/平尾、镜像和拉伸垂尾，共6个有效实体；另一轮只调整翼尖草图，读回主翼总展148→168mm，其他零件边界/体积保持，仍是同一工程。第三轮收到真实等轴测/俯视/侧视图并报告剩余外观问题。Agent曾将半展和总展混算，复查真实bounds后自行纠正；不能把它第一轮口头数值当成测量事实。保留折线翼型棱线、平板垂尾、翼根过渡及未验证加工/装配等限制。摘要：[`native-model-results.json`](../desktop/validation/native-model-results.json)。

该真实生产Electron/DSH流程观察到文字增量8/5/29次、思考版本614/82/349次及13张工具卡片，大小窗切换保留草稿和阅读位置；有外部窗口获得焦点的情况，未据此声称系统级焦点已完整通过。新滚动修复区分用户滚动和布局造成的scroll事件，避免晚到的布局事件关闭跟随；用户读历史后点回最新继续跟随。界面夹具另验证排版、设置和紧凑输入框。上述次数是采样状态版本，不是token或性能指标。

### 飞机：看图发现问题→同工程修改→重新观察

2026-11-13 使用实际 `desktop/main.mjs`、真实 DSH 和独立 FreeCAD 工程完成三轮对话，非替身 IPC：先获取等轴测/俯视图找问题，再提出参数计划，点击确认后更新原工程，最后再次获取图片复查。六个参数分别改为 length=140、bodyWidth=10、bodyHeight=12、span=130、wingThickness=2、tailSpan=50；确认前指纹不变，执行后仍为同一文档令牌和三个有效单实体。保存前后原生文件，私有数据未导出为公开样例。

实际改善是更修长的机身、更薄的翼面及更大的主尾翼间距；缺少垂尾、圆滑机头和翼型等结构问题仍未解决，当时的参数工具无法补齐；v1.2.0的原生接口验证另列于下。Agent 曾将透视观感误说成不对称，独立坐标镜像检查确认主翼/尾翼平面轮廓对称；第四轮加载补充后的视觉核对说明，模型读取坐标和新截图后明确纠正。不能把首次看图意见当成几何事实。

四轮真实文字版本数为22、11、22、23，reasoning版本数为212、304、280、212（采样观察计数，不是token数/性能指标）。截图工具执行中及返回状态可见；第二轮快速读取/提案在采样时已结束，不声称看到每个工具的瞬时执行态。第一、四轮生成中切换完整/小窗，草稿、renderer输入焦点、历史阅读位置保持；后续自己的应用渲染截图检查确认预览展开后小窗对话仍有158 CSS px，输入框/发送按钮固定可见，设置滚动后关闭/保存可见，六参数计划可查看/取消。系统级焦点、所有全局快捷键与多屏没有完整验收。

v1.1.1 活动视图判断复用外部 FreeCAD MCP 的 MIT 实现，单独真实GUI测试验证三维标签接受/表格标签拒绝，见 [`view-context-results.json`](../desktop/validation/view-context-results.json)；完整上游MCP server未安装。来源版本与许可见[复用记录](../research/agent-skills-tools/README.md)。

## 原生复杂模型与连续修改实测

### Electron模型启动回归（2026-11-13）

用户实际输入“我想做一个飞机模型”触发 `Unsupported/no-context`。已复现：Electron45.3.1内置Node24.22.2以 `ELECTRON_RUN_AS_NODE` 启动DSH时，原生require-builtin模块不可用。此前4轮复杂模型测试从独立Node启动，没有覆盖这条桌面路径，不能作为该路径已通过的证明。

修复为桌面启动器传递独立Node路径，Harness启动前探测并使用它，拒绝Electron运行时并清除run-as-node变量。首次复测还发现模型返回 `example:airplane, changes:{}` 被误拒绝，已修复为新建示例采用默认值；更新已有模型仍拒绝无变化参数。

新增[`Electron回归记录`](../desktop/validation/electron-runtime-results.json)：真实Electron主进程中调用同一个Session/Harness，DSH实际子进程为独立Node24.22.3；两轮真实请求“我想做一个飞机模型”“机翼展长改成120毫米，其他不变”均规划、确认并执行成功。生成三个有效Body，修改翼展保留机身与尾翼，保存原生飞机工程。回归使用隔离工作区，不覆盖用户数据，不等同于完成UI点击验收。

显式复现命令：设置已有DSH登录配置与 `FREECAD_EXE` 后运行 `node desktop/test/run-electron-harness.mjs`。它会打开测试CAD并请求模型，不随普通 `npm test` 自动执行。桌面运行时错误的技术摘要脱敏保存在私有 `model-errors.log`，对话不再倾倒原生诊断栈。

后续排查发现已有旧助手进程会继续使用加载时的代码，再次启动只会唤起该进程。v1.0.1新增窗口和界面版本标识；本次在实际窗口核对新版本、独立Node子进程，并从实际会话及CAD读回创建成功。此观察不替代隔离回归，也不公开真实会话或用户工程。验证部署时必须区分磁盘代码版本、隔离测试进程和用户正在操作的进程。

新增能力与复现步骤见[原生设计指南](native-designs.md)。当前成功证据：
