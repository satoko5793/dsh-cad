# 产品目标：从一句想法到可制作的实物

更新日期：2026-11-13。本文记录已确认的产品方向；实现进度与验收任务见[实施路线](roadmap.md)。

## 为谁解决什么问题

面向有实际制作需求、但不熟悉专业 CAD 的普通人。他们可能想固定一个设备、给电路板做个外壳，或连接两个现成零件。用户首先描述用途，系统帮助把用途转成可检查的设计要求，并引导完成制作。

目标体验是：**说清用途 → 补齐关键信息 → 看懂方案 → 用普通话修改 → 得到制作资料 → 加工组装 → 反馈修正。**

系统应能接住“这里挡住了，挪开一点”“这个盖子要经常拆”“我想把它固定在桌子下面”等表达。照片、草图、指认位置是后续输入能力，目前尚未实现，不能在界面中提前承诺。

## 成功交付是什么

| 成果 | 用户能得到什么 |
|---|---|
| 需求记录 | 用途、现有物品尺寸、安装位置、已确认条件、尚未确定的信息 |
| 零件方案 | 独立零件、用途、连接关系和修改后的影响说明 |
| 加工文件 | 按零件提供的文件、数量、材料和加工方式，明确文件版本 |
| 配件清单 | 螺丝等标准件的规格、数量和对应位置 |
| 装配说明 | 放置顺序、固定方法、工具与关键注意点 |
| 验证与修订记录 | 哪些经过计算、实物检查或用户确认，哪里仍待验证 |

当前只能交付其中的模型、参数、版本及几何文件；其余是产品建设目标。

## 交互原则

**先理解用途。** 用户说“固定设备”时，先弄清设备、固定面、拆卸需求及必要尺寸，再决定结构。一次优先问一个最影响结果的问题，说明为什么需要它。

**让用户使用日常语言。** 不要求先理解拉伸、布尔、工作平面等术语。回复先说结果与变化，详细测量按需展开。

**区分可采用默认值和必须确认的信息。** 普通外观或非关键尺寸可以提出具体默认值并告知；配合尺寸、现有物品孔位、加工方式和连接条件需要确认或标记待定。

**修改有明确对象与影响范围。** “底座厚一点”应关联到底座，保留未要求修改的部分。若连接关系导致其他零件位置随动，应解释原因。多种目标都可能时先澄清。

**用证据说明结果。** 实体有效、孔槽符合需求、装配可行、能够加工和实际使用是不同层面的结论。未执行的检查必须标记，不用模型自述代替验证。

**把打样反馈接回设计。** 用户说“孔偏了”“盖子扣不上”，系统应帮助确定对象和需要测量的量，将反馈转成修改，再检查受影响的关系。

## 第一阶段聚焦范围

以单人、本地使用和简单机械结构为基础，先完成一个可实际打印、装上电路板并固定盖子的控制盒。优先学习可重复使用的结构：支撑柱、螺丝连接、盖板定位和接口开口。

长期可扩展到其他加工方式、照片与草图输入、复杂装配及更多物品；近期取舍以能否推进控制盒实物闭环为依据。特征树、框架替换、云端部署等不是当前完成目标的前置条件。

## 怎样判断产品有用

阶段验收关注用户是否完成制作：能否补齐关键输入、看懂并修改设计、把文件交给加工方、买齐配件、照说明装起来，以及反馈后能否得到有效修正。模型数量和对话轮次只用于观察过程，不能单独证明任务完成。

暂不设没有基线支撑的成功率或耗时承诺。先用控制盒试点记录澄清次数、修改次数、加工问题、装配问题和修订结果，再决定后续指标。
