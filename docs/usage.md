# 使用指南

当前主要运行环境为 Windows。默认入口 `npm start` 为 Electron 桌面 Harness；保留的网页与 CadQuery 原型改用 `npm run start:web`。桌面接入 FreeCAD 1.1.4，尚不连接 SolidWorks/Fusion。能力边界见[验证记录](validation.md)。

## 桌面开发版启动

准备 Node.js 24.9或更新版本，以及已安装或完整解压的 FreeCAD。仓库根目录执行：

```powershell
npm ci
npm run desktop:runtime
npm start
```

首次点“连接FreeCAD”，助手自动准备连接组件并复用同一个CAD窗口；找不到安装位置时选择FreeCAD.exe，也可用FREECAD_EXE指定。无需手动执行宏或Python。首次组件安装遇到已打开的旧CAD时，提示保存后重开一次；后续支持原窗口升级。当前没有独立安装包，建模在真实FreeCAD中显示。详见[连接与单窗口使用](cad-connection.md)。

桌面启动器会把实际的独立 Node.js 路径传给模型服务，DSH不在Electron内置Node环境运行。直接启动Electron而未使用启动器时，可以通过 `GOUXING_NODE_EXE` 指定独立 `node.exe` 的绝对路径（24.9或更新），或确保它位于PATH。出现 `Unsupported/no-context` / `require-builtin` 的旧版错误时，退出助手并通过本机 `start-desktop-local.cmd` 或 `npm start` 重开，再重新发送原话；CAD和对话数据保留。

v1.0.1开始在原生窗口标题和完整界面标题栏显示版本。再次双击启动器会唤起已有窗口，仍在运行的旧进程不会自动加载磁盘上的修复：更新后需要真正退出旧助手，再打开并核对版本。CAD保持打开，会话和草稿恢复；不要在已有任务执行中强行结束进程。仅确认代码已更新或隔离测试成功，不能替代实际窗口版本及功能检查。

1. 输入“做一个四孔安装板”，查看默认80×40×5mm、四孔6mm计划，确认执行。
2. 在 FreeCAD 特征树选中整个 `ThroughHoles` 或 `MountingHoles`，说“孔径改成8毫米，其他不变”，确认后四个孔一起修改。当前不支持单孔或面/边选择的修改。
3. “撤销”“重做”会准备对应的原生事务计划；“另存原生工程”选择新的 `.FCStd` 路径后确认。首版拒绝覆盖已有文件。
4. 右上角缩为小窗/展开。可拖动标题栏、调整窗口边缘、切换置顶；`Ctrl+Alt+Space` 呼出/收起，`Ctrl+Alt+M` 切换形态。收起不会取消任务。
5. 选择或设计发生变化时旧计划失效，请重新发起需求。暂停只阻止尚未执行的操作；当前原生事务不能即时中断。超时后先检查 CAD，应用不会自动重发。

以上常用、精确指令走本地规则，不请求大模型；其他表达和讨论使用 DSH。特殊尺寸要求不会被悄悄替换为默认安装板，首版不支持的操作会说明限制。

现已扩展到原生多零件：可说“做一个带盖控制盒”“做一个小龙门架”“生成一个简化飞机”，再通过对话或右侧“设计尺寸”连续修改。零件列表会选中对应CAD Body，确认区列出前后尺寸与受影响零件。旧实例需保存工作后重开助手，并按“升级连接”提示启动新版连接；旧CAD保持打开。完整流程及边界见[原生设计指南](native-designs.md)。

v1.2.0还可用自然语言要求圆滑机身、渐缩机翼、增加垂尾、放样/旋转、圆角、阵列、参数表或原生特征修改。Agent通过现成66项原生工具准备操作，确认前可展开每项接口参数；修改已有工程时无需重新创建。原生模型用草图约束、属性或表格修改尺寸，旧配方面板不负责重建通用原生模型。设置中启用“原生CAD接口”组及freecad-native技能；旧助手重开核对v1.2.0，并按提示升级CAD宏。详见[原生接口](native-interfaces.md)。

`desktop/.data/` 保留会话、草稿、附件副本、窗口设置和桥接记录。附件暂不解析，模型只获得文件名。关闭助手会要求确认，FreeCAD 保持打开，请自行保存未保存工程；再次启动恢复对话、重新读取连接，但不会重发未完成计划。原型的 `cad-studio/.data/` 保持独立，请分别备份。

v1.1.0 的“技能与工具”入口位于输入框下方，可启停工具与技能、导入 SKILL.md。对话会实时显示文字、模型提供的思考和工具活动；上翻历史不会被强制拉回。说“看看现在这个飞机模型，有哪些外观问题”可让 Agent 调用真实 CAD 截图，点击“观察”则仅在本机预览，不自动发送模型。连接组件由助手管理，优先在原窗口升级；首次未加载组件的旧CAD可能需保存后重开一次。完整说明见[Agent 技能与视觉检查](agent-tools.md)。

## 同时准备网页原型

准备 Git、Node.js 24.9或更新版本、Python 3.13，并确保 `node`、`npm` 和 `py -3.13` 在终端可用。在准备保存项目的位置执行：

```powershell
git clone https://github.com/satoko5793/dsh-cad.git
cd dsh-cad
npm run setup
```

安装脚本会安装根目录和应用目录的 Node 依赖，建立 `cad-studio/.venv`，按 `cad-studio/requirements.lock.txt` 安装 Python 依赖。

若 Python 已安装但 `py -3.13` 找不到，可在仓库根目录使用其实际路径创建环境，再继续安装：

```powershell
& 'D:\Python313\python.exe' -m venv cad-studio/.venv
& '.\cad-studio\.venv\Scripts\python.exe' -m pip install -r cad-studio/requirements.lock.txt
```

`D:\Python313\python.exe` 是路径示例，需要替换为实际位置。Node 依赖尚未完成时仍需分别在根目录和 `cad-studio/` 运行 `npm ci`。

## 模型连接

运行 `npm run dsh -- web`，在原版 DSH 界面配置自己的 DeepSeek API，或使用已有 DeepSeek 账号登录。凭据由 DSH 管理，不放在源码、浏览器代码或设计文件中。

| 配置 | 默认值及用途 |
|---|---|
| `DSH_HOME` | 未设置时为当前用户目录下 `.dsh`，选择已有 DSH 配置与登录所在目录 |
| `CAD_LLM_PROVIDER` | 默认 `deepseek-official`；使用已有账号登录时设为 `deepseek-account` |
| `CAD_LLM_MODEL` | 默认 `deepseek-flash`，选择该路由支持的模型 |

账号登录方式可在同一个 PowerShell 窗口中设置后启动：

```powershell
$env:CAD_LLM_PROVIDER = 'deepseek-account'
npm run start:web
```

已有登录在其他 DSH 目录时，需要同时设置 `DSH_HOME`。应用使用专用 `cad-studio` profile，保留原版 web profile。上述变量只选择已有路由，不会自动配置第三方网关或验证密钥。

CAD 引擎就绪不代表模型服务已连接。启动检测不会发起生成请求；实际连接和生成应分别确认。若切换配置，需要重启本应用服务才能让新的进程环境生效。

## 日常启动

桌面：`npm start` 或 `start.cmd`。网页原型：`npm run start:web` 或 `start-web.cmd`，打开 `http://127.0.0.1:3090`，已有网页服务会复用。通过终端启动时应保持终端打开。

| 命令 | 用途 |
|---|---|
| `npm start` | 启动桌面 Harness |
| `npm run start:web` | 启动保留的网页原型 |
| `npm run start:web -- --no-open` | 启动网页服务，不打开浏览器 |
| `npm run status` | 检查服务是否运行，不创建项目或请求模型 |
| `npm run harness` | 原版 DSH 界面，默认端口3080，以终端地址为准 |
| `npm run samples:import` | 导入明确选中的4个公开示例，保留已有同ID项目 |

Node 路径未加入 PATH 时，可在启动终端临时加入安装目录，或用包含实际 Node 路径的本地启动脚本。机器专用路径与凭据目录不提交到仓库。

本次测试机器的专用桌面启动器为 `E:\dsh\start-desktop-local.cmd`，复用已有 `DSH_HOME` 和 `deepseek-account` 登录；该机器配置不提交仓库。通用启动的模型变量仍按上表配置，桌面使用按数据目录隔离的 `gouxing-desktop-<摘要>` profile，不修改原型及原版 web profile。

## 网页原型：生成和修改

1. 新建零件，描述用途、形状和已知尺寸；也可以选择现有示例。
2. 生成后旋转、平移或缩放模型，查看尺寸与版本。默认长度单位是毫米。
3. 用普通话继续修改，例如“孔径改成8毫米，其他不变”。修改以当前选中版本为基础。
4. 直接修改尺寸时先点“预览修改”；确认后保存新版本，或取消恢复。预览30分钟后不可提交，需要重新预览。
5. 满意后下载当前保存版本的 STEP、STL 或建模源码；未保存的尺寸草稿或预览需要先处理。

多模块模型会显示模块名称、尺寸与实体数量。“底座厚一点”可以采用具体默认改变量并告知；存在多个可能目标时应先澄清。模块组合目前是静态几何，连接方式与实际可组装性仍需单独设计和验收。

## 看清组件并指定修改对象

对具有命名组件的模型：

- 指向模型中的零件，零件边缘与表面会高亮，下方显示名称、尺寸，对应组件卡片同步突出。
- 指向组件卡片可以反向高亮模型；点击卡片或模型中的零件可保持选中。键盘可通过组件按钮选择，画布获得焦点时按 Escape 取消。
- 拖动“分离程度”把组件拉开查看，用“合回原位”恢复。分离只改变显示，不修改设计尺寸、真实位置、保存版本或导出文件。
- 选中后可“只看选中”，再次点击显示全部；“修改这个组件”把输入焦点移到对话框，输入区显示本次修改对象。可直接说“把这个零件加厚1毫米”。选中对象会随请求传给模型，并记录在对应用户消息中。
- 取消选中或切换模型/版本会清除修改对象，避免把上一个版本的选择带入下一次修改。

旧的命名组件版本首次查看时会生成独立显示缓存，需要等待本地CAD计算，不请求大模型、不新增设计版本。未记录组件名称的旧模型保持整体展示；组件加载失败时显示提示，不根据包围盒猜测组件归属。

## 查找项目与查看测试结果

刷新页面或让页面重新获得焦点可更新左侧项目列表。可用 `http://127.0.0.1:3090/?project=<项目ID>` 直达已有项目，切换项目会更新地址栏链接。链接只能访问当前运行机器已有的数据，公开仓库不会自动获得本机项目。

在2026-11-13的测试机器上，左侧有“桌面小龙门架”和“小控制盒（盒身+盖子+内托盘）”；聊天和版本保存在对应项目内。其他机器需自行生成，公开导入清单不包含这两个项目。

## 文件与备份

`cad-studio/.data/` 包含项目聊天、参数、建模源码、历史版本、预览及导出文件，备份应覆盖整个目录。迁移时还需按 DSH 的方式处理模型登录配置；备份设计不等于备份登录。

STEP 用于几何交换，STL 用于网格展示和切片；可再生的参数化来源为脚本与参数，不能承诺导入其他 CAD 后恢复原生特征树。当前导出也不包含完整的材料、标准件和装配交付资料，相关建设见[实施路线](roadmap.md)。
