# 原生多零件建模与连续修改

更新：2026-11-13。桌面开发版已从固定四孔板扩展到数据驱动的 FreeCAD 原生多零件特征。“多零件”指独立 Body 的静态组合，尚无装配约束或运动求解。

| 可以试的需求 | 实际生成 | 连续修改 |
|---|---|---|
| 做一个带盖控制盒 | 盒体、空腔、四固定柱与盲孔；独立上盖、定位唇和通孔，共2个Body、7个特征 | 盖子加厚1毫米，盒身别动 |
| 做一个小龙门架 | 底座、左右立柱、横梁、带孔滑台，共5个Body | 滑台向右移动10毫米 |
| 生成一个简化飞机 | 多边形机身、主翼和尾翼，共3个Body | 机翼展长改成120毫米，其他不变 |
| 新建带双通孔的L形支架，并指定尺寸 | 模型组合通用草图、拉伸与切除，不使用上述预设 | 明确参数后继续修改长度、厚度或孔径 |

无尺寸的三个示例精确指令可离线生成计划；指定尺寸或其他表达使用 DSH。控制盒默认90×64×30mm、壁厚2.5mm、盖厚3mm；计划的“查看尺寸与变更”列出默认值。用户指定的数值不能被替换为默认。

这些是验证用结构：控制盒尚未按真实电路板、螺丝与打印工艺校核；龙门架尚缺紧固与导向结构；飞机有意相交的静态零件不代表可装配或可飞行。实体有效不等于加工、配合或强度通过。

## 使用流程

1. 连接新版 FreeCAD，提出需求，核对零件和尺寸，确认执行。
2. 右侧列表展示零件名称与实际外形尺寸；点击会在连接的 CAD 中选择对应Body。小窗也有选择器；“回到 CAD”只在点击时切换焦点。
3. 展开“设计尺寸”输入数值，点“准备尺寸修改”。此时尚未写入，确认区显示前后数值和涉及零件；确认后才重建。
4. 也可继续对话说“盖子厚一点”或选中零件后说“这个再加厚1毫米”。模型读取真实选择与参数，歧义需澄清；修改仍经过结构和数值校验。
5. 参数更新保留原Body、草图及特征对象，处于同一事务；失败尝试中止整个事务。撤销/重做作用于最近原生事务，需确认。
6. 可另存新的 `.FCStd`，通过“打开原生工程”准备打开计划；其他工程保留，已有文件不覆盖。未知工程只读。

完整/小窗共享草稿、计划、暂停、选择及任务记录。最近20次操作持久化，界面显示最近6次；重启时未完成记录标为待核对，不自动重放。

旧助手和宏不会热更新。保存自己的工作后重开助手；遇到“升级连接”，点击会启动新版专用CAD实例，旧实例与未保存工程保留。本机启动器仍为 `E:\dsh\start-desktop-local.cmd`。

## 实现边界

结构校验在 `desktop/design.mjs`，原生操作在 `desktop/freecad/features.py`。支持1至12个Body、每个1至12个特征、合计最多72个特征、1至48个参数；矩形（含嵌套环）、多圆和3至32顶点多边形草图；XY/XZ/YZ平面的Pad/Pocket、深度或贯穿切除、Body的XYZ位置。尺寸算式仅含参数名、有限数字、四则运算与括号，不执行模型提供的程序。

初次创建可以组合通用特征；后续只更新已有参数，不支持追加/删除特征、圆角、曲面、单孔/单面编辑或任意第三方工程写入。原生草图当前用Block约束生成，配方存入 `HarnessInfo.DesignJson`，尚未变成Spreadsheet/表达式驱动系统。直接手工编辑不会自动反写配方；检测到差异便停止重建，尚无自动合并手工变更流程。

编辑保护使用稳定的原生草图、特征属性与归一化测量签名，避免保存重开时BRep字节顺序变化造成误判。写入还会重读实例、文档、选择及实时指纹。实际建模步骤写出进度，结果确认前先发布新快照。

每个数据目录使用独立 `gouxing-desktop-<摘要>` DSH profile，测试与用户工作区隔离；凭据仍由同一 `DSH_HOME` 管理，不复制到前端或仓库。附件仍只保留副本及文件名。

桌面模型服务使用独立Node.js，通过启动器自动传递路径；不使用Electron内置Node。新建示例时空的尺寸修改项表示采用默认值，不能误当成“没有指定修改参数”。“我想做一个飞机模型”经过真实模型规划，不需要改成固定测试口令。

## 测试

`npm test` 当前21项：桌面15、原型6。显式设置 `FREECAD_EXE` 后可运行 `node desktop/test/native-check.mjs`（旧板9组）、`node desktop/test/complex-check.mjs`（多零件20组）、`node desktop/test/reopen-check.mjs`（保存重开和手改保护27组）。它们有重叠，不累加为独立能力；原生文件留在私有 `.data/`，测量摘要在 `desktop/validation/`。

真实模型验证还需已有DSH登录，运行 `node desktop/test/model-complex-check.mjs`，会请求模型。已通过4轮创建/修改，L支架另核对80×50×45mm外形和双通孔解析体积。普通测试不运行这些GUI或模型检查。手动窗口验收及未覆盖项见[验证记录](validation.md)。

桌面启动路径另用 `node desktop/test/run-electron-harness.mjs` 显式验证：从真实Electron主进程调用独立Node和DSH，执行“我想做一个飞机模型”及翼展修改两轮。它会请求模型并打开隔离CAD，普通Node模型测试不能替代该回归。
